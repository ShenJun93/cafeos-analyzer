- `db/migrations/001_analyzer_core.sql` — Analyzer baseline contract.
- `db/contracts/control_tower_core.sql` — reviewed/staging-verified Control Tower contract.
- `supabase/migrations/20260921005530_analyzer_core.sql` — CLI-generated Analyzer baseline migration.
- `supabase/migrations/20260921005532_control_tower_core.sql` — CLI-generated Control Tower migration.
- `supabase/tests/database/control_tower_rls.test.sql` — reproducible pgTAP RLS/workflow tests.
- `docs/CONTROL_TOWER_IMPLEMENTATION_SLICE.md` — thin-slice product boundary.

`tests/supabase-migration-sync.test.mjs` requires migration contents to remain byte-equivalent to the canonical baseline/contract.

## Verification history

The Control Tower contract first passed isolated `cafeos-staging` tenant/RLS/integrity tests and Supabase advisors using synthetic data. Migration history was then generated with **Supabase CLI 2.117.0**, not manually timestamped.

`.github/workflows/supabase-db.yml` starts a blank local Supabase stack, applies ordered migrations, runs `supabase test db`, reports migration state and tears the stack down.

## Analyzer core

Each normalized line has deterministic `source_record_key`; uniqueness on `(tenant_id, source_namespace, source_record_key)` keeps overlapping imports idempotent. Import fingerprints are unique within `(tenant_id, source_namespace)`.

## Control Tower stable graph

### Stores
- tenant/source identity: `(tenant_id, source_namespace, external_key)`
- line items retain raw store text and gain nullable stable `store_id`

### Customers
- tenant-local customers and deterministic customer identifiers
- matching HMACs; no fuzzy matching
- identifier rows are server-only in the first slice
- line items gain nullable stable `customer_id`

Composite foreign keys include `tenant_id` to reject cross-tenant references even when application code is wrong.

## Attention → Action → Measurement

- Attention items carry deterministic key, metric/scope/baseline/current/delta/coverage/evidence/detector version; clients do not author trusted numeric insights.
- Actions are bounded to investigate/follow-up/segment/experiment-hypothesis; viewer is read-only.
- Action status history is generated by database trigger.
- Measurement windows start pending with null trusted values; clients cannot write measured values; delta is generated by Postgres.

This records before/after measured change without claiming causality.

## Supabase grants + RLS

Grants and RLS are separate controls. The schema revokes anonymous product-table access, explicitly grants minimum authenticated operations, enables RLS on all new public tables, and keeps matching identifiers/trusted metric writes server-owned.

## Production gate

Migration/RLS reproducibility is not authorization for production merchant data. Before real merchant data: define retention/deletion, rollback/recovery, verify authenticated request context, re-run advisors after DDL changes, and make an explicit production release decision.

## Deferred

No campaign delivery, loyalty balances, payment, inventory, accounting/payroll, generic project management or full experiment/exposure/conversion system in this thin slice.
